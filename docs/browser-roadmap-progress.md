## 1. Обновления и подлинность

Начало: 2026-10-20. Исходное состояние: обновления только через ручную
установку релиза; подписанного канала обновлений и системной подписи Windows нет.

Критерии проверки: подмена подписанных метаданных/файла отклоняется,
повторная установка старой версии не предлагается, сетевой сбой не мешает
работе браузера, обновление не перезаписывает работающий процесс и профиль.
Пакетные установки Linux обновляются пакетным менеджером.

Публикация настоящего канала и проверка обновления между двумя сборками,
а также подпись Windows доверенным сертификатом отмечаются отдельно от
модульной проверки механизма.

Реализовано:

- Публичная идентичность Ed25519 в `common/update_key.hpp`; закрытый ключ создан
  в игнорируемой папке `local/release-signing`, права 0600. Пользователь подтвердил:
  пока выполняется подпись канала, без сертификата Windows.
- Ежедневная проверка при обычном запуске, отключаемая настройкой. Приватный
  запуск проверку не выполняет. Preview-канал учитывает prerelease-релизы GitHub.
- Окно версии/обновлений на русском и английском, скачивание и подтверждение
  установки. Метаданные привязаны к одному тегу, имеют срок действия и номер
  последовательности; подпись и SHA-256 обязательны. Старый канал отклоняется.
- Загрузка в отдельный каталог, ограничения размера/времени, отмена и очистка
  незавершённых файлов, хеширование вне потока интерфейса. Установщик запускается
  после завершения Chromium; `.deb`/`.rpm`/Arch остаются за пакетным менеджером.
- Скрипты подписи фактических ассетов и GitHub Actions workflow. Отдельный workflow
  сравнивает закреплённый Chromium с официальным индексом CEF дважды в неделю.
- Linux `.run` проверяет запуск нового runtime до замены существующей установки.
- После автоматического отказа передать закрытый ключ в GitHub и условного ответа
  пользователя выбран локальный способ подписи. Ключ в GitHub не передан; workflow
  выполняет только проверку опубликованных файлов по открытому ключу.

## 3. Пароли и перенос между устройствами

Начало: 2026-10-20. Пользователь выбрал зашифрованный файл ручного переноса
вместо сервера. План: отдельное хранилище под основным паролем, явное сохранение
и заполнение логинов на HTTPS-сайтах, управление записями, блокировка и
зашифрованный экспорт/импорт. Закрытый ключ канала обновлений не используется.

Критерии: неверный пароль и подмена файла отклоняются без изменения данных;
в профиле/логах/диагностическом отчёте нет открытых паролей; заполнение требует
действия пользователя и совпадения origin, не работает в приватной вкладке,
iframe или на HTTP. Проверки используют только вымышленные логины.

Наблюдение для пункта 5: ранний `--url` иногда остаётся на bootstrap `about:blank`;
проверка паролей явно открывает и ждёт HTTPS-страницу. Требуется отдельная
проверка отложенного начального перехода и навигации при создании вкладки.

Реализовано до итоговой проверки:

- Отдельный AES-256-GCM/scrypt vault под основным паролем, блокировка вручную
  и через 15 минут, смена пароля, добавление/изменение/удаление логинов.
- Явное заполнение и сохранение после подтверждения на HTTPS, проверка origin,
  основного frame, формы и навигации. HTTP, приватные вкладки и iframe отклоняются.
- Ручной зашифрованный экспорт/импорт логинов по выбранному пользователем варианту;
  отдельный пароль файла, сохранение локальных конфликтов, зашифрованная копия.
- Панель RU/EN, маскировка секретов, Ctrl+Shift+Y. Пароли не включаются в отчёт
  или обычный TOML профиля. CEF-сохранение/автовход отключаются при наличии prefs.
- 64 CTest-сценария без ошибок после добавления проверок криптохранилища.
  Первый настоящий GUI-прогон — PASS: перезапуск, перенос, HTTPS-заполнение,
  отказы HTTP/другого origin/iframe/private, подтверждение и отсутствие утечек
  в логах/отчёте. Итоговый RU/EN/125% прогон и Windows ещё проверяются.

Оговорки: это автозаполнение логинов и ручной перенос именно паролей. Адреса,
платёжные карты, passkeys, фоновая синхронизация и перенос прочих данных не
реализованы. Shadow DOM, многошаговые и нестандартные формы могут потребовать
ручного ввода. Забытый основной пароль восстановить нельзя.

## 4. Расширения

Начало: 2026-10-20. Сначала проверяется доступность встроенных команд
Chromium для наблюдения за фактически загруженными расширениями и их
жизненным циклом. Наличие записи enabled в registry само по себе не доказывает
успешную загрузку. Дальше — управляемые обновления, ошибки и ограничения API.
Публичный remote-debugging endpoint для этого не открывается.

Проверка движка: `Extensions.getExtensions` → `Method not available`,
`Target.attachToBrowserTarget` → `Not allowed`, встроенная `chrome://extensions/`
→ `net::ERR_ABORTED`. Одинаково с тестовым расширением и без него;
CEF 154, отдельный CPU display. Лог: `artifacts/build/extensions-engine-probe.log`,
`artifacts/extension-lifecycle/*/aura.log`. Экспериментальные hooks удалены.
Будет улучшен поддерживаемый путь с сохранением сессии и перезапуском;
равенство всех Chrome API без изменения движка не заявляется.

Дополнительная проверка завершения: принудительное закрытие больше не подтверждает
произвольные owned-диалоги (в том числе сохранение логина); разрешается только
закрытие страницы с beforeunload.

Реализовано до итоговой проверки пункта 4:

- Перезапуск из менеджера расширений после подтверждения, сохранение обычной
  сессии независимо от настройки обычного запуска, завершение CEF до старта
  нового процесса, закрытие приватных вкладок и блокировка vault.
- Раздельные состояния: запрошенная при старте загрузка, наблюдавшаяся активность,
  ожидающее отключение/обновление. Активность подтверждается extension context,
  target или успешно загруженным popup; enabled не называется Running.
- Проверка новой версии из магазина по кнопке, подсветка новых разрешений при
  обновлении, сохранение выключенного состояния и pin, отказ старым версиям.
- Отмена/45-секундный предел скачивания, ограниченное фоновое чтение CRX, защита
  от завершения старого запроса после отмены, откат изменений registry при ошибке.
- Исправлена потеря начального URL при bootstrap: исходный адрес хранится отдельно
