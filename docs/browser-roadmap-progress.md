## 1. Обновления и подлинность

Начало: 2026-10-20. Исходное состояние: обновления только через ручную
установку релиза; подписанного канала обновлений и системной подписи Windows нет.

Критерии проверки: подмена подписанных метаданных/файла отклоняется,
повторная установка старой версии не предлагается, сетевой сбой не мешает
работе браузера, обновление не перезаписывает работающий процесс и профиль.
Пакетные установки Linux обновляются пакетным менеджером.

Публикация настоящего канала и проверка обновления между двумя сборками,
а также подпись Windows доверенным сертификатом отмечаются отдельно от
модульной проверки механизма.

Реализовано:

- Публичная идентичность Ed25519 в `common/update_key.hpp`; закрытый ключ создан
  в игнорируемой папке `local/release-signing`, права 0600. Пользователь подтвердил:
  пока выполняется подпись канала, без сертификата Windows.
- Ежедневная проверка при обычном запуске, отключаемая настройкой. Приватный
  запуск проверку не выполняет. Preview-канал учитывает prerelease-релизы GitHub.
- Окно версии/обновлений на русском и английском, скачивание и подтверждение
  установки. Метаданные привязаны к одному тегу, имеют срок действия и номер
  последовательности; подпись и SHA-256 обязательны. Старый канал отклоняется.
- Загрузка в отдельный каталог, ограничения размера/времени, отмена и очистка
  незавершённых файлов, хеширование вне потока интерфейса. Установщик запускается
  после завершения Chromium; `.deb`/`.rpm`/Arch остаются за пакетным менеджером.
- Скрипты подписи фактических ассетов и GitHub Actions workflow. Отдельный workflow
  сравнивает закреплённый Chromium с официальным индексом CEF дважды в неделю.
- Linux `.run` проверяет запуск нового runtime до замены существующей установки.
- После автоматического отказа передать закрытый ключ в GitHub и условного ответа
  пользователя выбран локальный способ подписи. Ключ в GitHub не передан; workflow
  выполняет только проверку опубликованных файлов по открытому ключу.

Проверка реализации на Linux:

- Linux Release собирается. Итог: **47/47 CTest, 18/18 Python-тестов**.
- Тесты менеджера обновлений проверяют успешную цепочку метаданные → подпись →
  скачивание → SHA-256, сохранение защиты от отката после перезапуска, сетевой
  сбой, подмену и удаление неполных загрузок при отмене. CEF API инициализируется
  в тестовом стенде до JSON-разбора.
- Официальный индекс CEF проверен 2026-10-20: закреплённые Linux/Windows
  Chromium 154.0.8037.98 совпадают с максимальными стабильными версиями индекса.
- GUI на отдельном Weston Pixman/Xwayland SHM, GLX отключён: RU/EN окно обновлений,
  отключение фоновой проверки, явный запрос, отмена и завершение — **PASS**.
- Настоящий браузер прочитал опубликованный GitHub-канал, проверил подпись
  Ed25519 и текущий номер версии — **PASS** (`artifacts/updates-smoke/live-channel-PASS.txt`).
- Обычные вкладки/навигация/восстановление сессии и отдельная полная проверка
  настроек после изменения — **PASS**.
- `aura-update.toml` и `aura-update.toml.sig` опубликованы в v0.2.0-preview.3.1.
  Подписаны фактические файлы семи типов; повторная загрузка метаданных,
  проверка подписи и сравнение с серверными SHA-256/размерами GitHub — **PASS**.

Установщики релиза v0.2.0-preview.3.1 не заменены: новый менеджер пока находится
в исходниках и локальной сборке.

Windows CI 39437988545: компиляция и все C++-тесты обновлений прошли. Python-тест
подписи выявил различия LF/CRLF в PEM-выводе OpenSSL. Исправлено сравнение
идентичности открытого ключа с нормализацией пробельных символов; добавлен
отдельный сценарий CRLF. Повторный **Windows CI 39438854162 — success**:
сборка, модульные проверки, настоящая GUI-проверка и установщик.

Итоговая проверка перед переходом к пункту 2:

- Полный Linux-переход: отдельная сборка с тестовым предыдущим номером
  последовательности → настоящий GitHub-канал → подпись → загрузка настоящего
  `.run` → подтверждение в UI → закрытие CEF → установщик. Итоговый исполняемый
  файл в тестовой установке побайтно совпал с опубликованным; запуск через
  установленный launcher и сохранённая закладка — **PASS**
  (`artifacts/updates-journey/install-PASS.txt`). Это синтетическая предыдущая
  сборка с уже встроенным updater; исторические старые сборки его не имеют.
- Отдельно проверено: приватный запуск с включённой настройкой обновлений не
  выполняет проверку; просроченное предложение требует заново проверить канал.
- Публичный workflow проверки метаданных и всех семи скачанных ассетов:
  **39438157058 — success**. Закрытый ключ для этого не используется.

Оговорки выпуска: доверенная подпись Windows исключена по решению пользователя;
полный переход через updater на установленной Windows ещё не воспроизведён
(Windows CI проверяет сам браузер, модули и установщик). Новые установщики нужно
выпустить после следующего этапа, затем повторить проверку перехода на их точных
бинарниках. Проверка новых CEF в CI сообщает о необходимости обновления, но не
заменяет ручную интеграцию и проверку нового runtime.
