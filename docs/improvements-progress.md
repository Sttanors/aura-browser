### B1 — реализация

Поиск существующей папки использует ту же нормализацию регистра RU/EN и пробелов,
что и её создание. Ошибка создания папки прерывает импорт с понятным сообщением
RU/EN, вместо помещения записей «Без папки». Работа идёт с копией профиля, поэтому
ошибка сохраняет исходный профиль. Добавлены регрессии настоящего HTML-импорта:
сопоставление двух регистров, сохранение после перезапуска и атомарный отказ при
лимите 128 папок. Сборка Linux PASS. Пять тестов `Imports.*Folder*` PASS, включая
новые регрессии, повторную загрузку профиля и сохранность TOML при отказе.

### B2 — реализация

Сохранение, редактирование и экспорт используют общий список разрешённых схем,
включая file://, about:blank и страницы установленных расширений. Исполняемые
javascript:/data: адреса не сохраняются. HTML экранирует URL и подписи. Если старый
профиль всё же содержит неподдерживаемые адреса, экспорт показывает их число до
выбора файла. Добавлена регрессия сохранения/редактирования/экспорта локального
документа после перезапуска, сохранения тегов и точного числа исключённых адресов.
Linux build, 4 Bookmarks-теста и изолированный GUI bookmarks PASS: нативный Save,
отмена, UTF-8 путь, экранирование HTML, массовые действия, RU/EN и повторный запуск.

### B3 — реализация

Команда сначала проверяет исключения, захват/воспроизведение медиа и состояние
страницы. Переключение на другую вкладку или создание стартовой вкладки, а также
выход из split выполняются только после успешного подтверждения freeze от CEF.
Добавлены GUI-регрессии: отказ для домена из исключений и Web Audio сохраняет
активную вкладку и количество вкладок.
Изолированный GUI manual/exceptions PASS: реальный freeze/wake, неподвижный таймер,
сохранение формы/beforeunload, освобождение bitmap, отказ для media/domain без
смены фокуса. Старый сценарий приватной вкладки больше не зависит от лишней NTP.

### B4 — реализация

Домашняя страница использует тот же разбор authority, что и адресная строка:
проверяются hostname, IPv6, порт и управляющие символы. Явный HTTP/HTTPS сохраняет
поддержку локальных имён без точки; некорректный ввод не заменяет прежнюю настройку.
Добавлены проверки ошибочных IPv6/портов/IPv4/hostnames и корректных localhost,
intranet, IPv4, IPv6 и кириллического домена.
Linux build и полный CTest: 127 entries, 0 failures (8,65 с).

### B5 — реализация

Снимки, поиск/отмена удаления в UI и папки закладок используют общий независимый
от locale helper регистра RU/EN (включая Ё/ё). Другие UTF-8 символы сохраняются;
полный Unicode case folding для остальных языков не заявляется. Старые снимки с
различием только в регистре кириллицы не удаляются: при чтении добавляется свободный
суффикс имени с сохранением ID, окон и URL. Добавлены регрессии создания,
переименования, миграции двух старых снимков и повторного сохранения/загрузки.
Linux build, 9 Sessions/Bookmarks tests и GUI sessions PASS: save/rename/update,
delete/undo, настоящее восстановление в новых окнах, перезапуск, контейнеры,
split, RU и запрет приватных снимков.

### 1 — запоминание масштаба сайта: реализация

[Использование RU/EN](site-zoom.md).

Масштаб хранится по canonical hostname и контейнеру (схема/порт не разделяются,
как у нативного host zoom Chromium). Применяется в новых вкладках, при навигации
и после перезапуска; открытые страницы того же хоста/контекста обновляются вместе.
Ctrl 0 удаляет переопределение и использует масштаб по умолчанию. Переключатель
«Запоминать масштаб для каждого сайта» находится в «Веб-страницы» и действует
сразу. Приватные значения хранятся отдельно в BrowserState, не попадают в TOML.
Schema15, до 1000 правил, проверка host/container/finite level и очистка правил
при удалении контейнера. Linux build и 129 CTest PASS (8,77 с).
GUI site-zoom PASS: настоящий CEF 100/120/144/83%, другой хост, новые вкладки,
контейнеры, private isolation, Ctrl 0, отключение/включение из RU UI и три запуска.
Приватный URL и значение не попали в TOML/backup. Подпись настройки проверена
визуально; отдельная панель и дополнительные декоративные индикаторы не добавлялись.

### 2 — правила контейнеров: реализация и проверка

### 3 — менеджер загрузок: реализация и проверка

Список переносится в общее состояние профиля; приватные записи фильтруются
по окну-источнику. Владелец и вкладка загрузки учитываются вместе, чтобы ID
вкладок разных окон не блокировали сон друг друга. Зарезервированные пути файлов
также общие для окон. Скорость берётся из CEF, ETA вычисляется при известном
размере. Для сбоя/отмены добавлен явный повтор в исходном контексте.
Ручная SHA-256 читает файл порциями в файловом потоке CEF, сравнивает ожидаемый
хеш либо только вычисляет; закрытие окна/удаление записи не оставляет callback
к уничтоженному UI. [Использование RU/EN](downloads.md).

Linux build без предупреждений и полный CTest: **132 entries, 0 failures** (8,88 с).
Новая регрессия SHA-256 использует известный digest `abc`, проверяет регистр,
неверный формат, отсутствующий файл и каталог. GUI `downloads` PASS:
реальная скорость/ETA, pause/resume/cancel из соседнего окна, обрыв HTTP и повтор,
сопоставление SHA-256 по независимому Python hashlib, ошибка формата с сохранением
ввода, совпадение/несовпадение, копируемый результат, приватная изоляция,
сохранение записей после закрытия источника и повтор из нового готового CEF frame.
Загрузка первого окна не блокирует сон вкладки второго с тем же локальным ID.
GUI `download-sleep` и `container-rules` на финальной сборке PASS.

CEF при отмене/сбое может прислать пустые метаданные: они больше не затирают
известные имя, путь и URL. Повторные OnBeforeDownload одного ID используют один
зарезервированный путь: автоматические сетевые попытки не создают суффиксы (2)…(6).
Новая ручная попытка получает отдельный путь и не перезаписывает предыдущий файл.
Приватные записи отфильтрованы также из счётчика боковой панели.
Визуально проверены RU скорость/ETA и окно результата SHA-256.
Windows CI запускается для нового коммита отдельно; публичные пакеты прежние.

### 4 — диспетчер задач: реализация и проверка (25 октября 2026)

CPU/память берутся из CefTaskManager в UI-потоке; вкладки renderer группируются
по Chromium child ID из доверенного frame identifier CEF. Наблюдатель CEF
удерживается только пока открыта хотя бы одна панель. Метрики общего
процесса не суммируются. Сырые заголовки системных задач CEF не выводятся, чтобы
не раскрывать URL/названия приватных страниц. Другие приватные окна скрыты.
Завершение доступно только известному renderer с видимыми вкладками; browser,
GPU, utility/extension и неизвестные процессы защищены. Подтверждение перечисляет
затронутые вкладки и повторно проверяет Task ID, process key, serial навигаций, состав
вкладок и актуальную задачу CEF. OS kill не используется. Отображаются процесс браузера и основные процессы
вкладок: отдельные iframe/worker/system tasks без доступного process ID исключены,
чтобы не показывать повторно их общие показатели.
[Использование RU/EN](task-manager.md).

Linux build без предупреждений; **135 CTest entries, 0 failures** (9,36 с).
GUI `task-manager` PASS: реальные CPU/footprint под контролируемой нагрузкой,
две связанные window.open-вкладки одного renderer (память учтена один раз),
отдельное обычное окно, защищённый browser process, отмена и отказ после навигации
в другом окне, скрытие приватных названий и отсутствие их в profile.toml.
Завершены renderer с бесконечным JS после загрузки и renderer с зависанием
до окончания загрузки; оба восстанавливаются перезагрузкой. CEF lifecycle 5/5.
После намеренного завершения страница показывает понятное состояние и кнопку
обновления; технический код `Renderer terminated` остаётся только в диагностике.
Флаг завершения сбрасывается при навигации; прекращается зависший индикатор загрузки.

GUI `hotkeys` и `commands` PASS: переназначение/отключение/конфликты и существующий
диспетчер клавиатуры/палитра. Shift+Esc имеет читаемую подпись, настраивается и
не обходит модальные диалоги. Новая команда доступна из меню Aura и палитры.
Финальный GUI также проверил RU/EN, окно 1000×740, настоящий UI 200%, клавиатуру,
и пункт меню при логической высоте 620: меню больше не обрезается снизу.
Визуально проверены таблица, подтверждение, русская панель и состояние завершённой
страницы; убрана дублирующая подпись у процесса браузера.

Особенности API проверены по исходникам закреплённого CEF:
[наблюдатель TaskManager](https://github.com/chromiumembedded/cef/blob/426920c/libcef/browser/task_manager_impl.cc)
создаётся заново каждым GetTaskManager, поэтому ссылка удерживается до закрытия
последней панели. Идентификатор renderer берётся из доверенного CEF frame token;
изменения запуска subprocess и IPC не потребовались. Статистика не суммирует
повторные метрики общего процесса, неподдержанный формат отключает завершение.

### 5 — библиотека «Прочитать позже» и текстовые офлайн-копии

Реализованы общая для окон профиля библиотека, извлечение статьи локальным
Readability, поиск по полному тексту с RU/EN-регистром, ручная отметка прочтения,
обновление копии по тому же URL и удаление с подтверждением. Вход через заголовок
закладок и палитру команд. Панель нативная, с клавиатурным фокусом и прокруткой.
Режим чтения использует тот же модуль извлечения.

Отдельный reading-list.toml записывается через временный файл и атомарную замену;
ошибка сохраняет старые данные в памяти, повреждённый файл не перезаписывается.
Приватные страницы и результаты устаревшей навигации не сохраняются. Лимиты:
100 статей, 512 КиБ на статью, 8 МиБ суммарно; превышение отклоняется целиком.
HTML создаётся при открытии из экранированных текстовых блоков, CSP запрещает
скрипты и внешние ресурсы. Копии работают без сайта и после перезапуска.
Подробности и ограничения: [reading-list.md](reading-list.md).

сохранение/обновление, статус прочтения, RU-поиск по тексту, ограничение вставки
запроса, вход из закладок с клавиатуры, исключение приватной страницы, чтение
после остановки HTTP-сервера и двух перезапусков, отмена/подтверждение удаления.

## 10. Перенос вкладок между окнами — реализация и проверка

Вкладка передаётся между окнами одного профиля вместе с живым CEF-браузером:
без LoadURL, закрытия документа или запроса beforeunload. Контейнер, приватность,
история, формы и параметры страницы сохраняются. Родительская связь снимается,
дети остаются в исходном окне и поднимаются к прежнему предку. Рабочее пространство
назначается по окну назначения. Вставка перед вкладкой принимает её группу,
выбор окна через меню сохраняет совместимую прежнюю группу.
Приватные вкладки принимают только приватные окна, обычные — только обычные.
Последняя перенесённая вкладка оставляет стартовую страницу в исходном окне.

Предусмотрены перенос мышью на панель другого окна и выбор окна через контекстное
меню / Ctrl+K. Область приёма показывает линию вставки и подпись, Escape отменяет
жест. Кнопки окна, страницы и перекрытые другими окнами области не принимают
перенос. Размеры и координаты учитывают масштаб обоих окон. Диалоги, незавершённые
операции, расчёт контрольной суммы и закрытие дубликатов временно блокируют перенос.

Обработчики CEF, перерисовки, IME и DevTools переключаются на новое окно;
одноразовые незавершённые DevTools-запросы отбрасываются. Счётчики живых CEF
и привязка загрузок передаются новому окну. Неизменяемый native parent OSR
удерживается вкладкой до её закрытия; его обработчики отключаются при удалении
исходного контроллера, поэтому закрытие старого окна не оставляет висячих ссылок.

Окончательная Linux-сборка без предупреждений и ошибок. Все 163 CTest PASS
(8,51 с). Tab-transfer GUI PASS: реальные нативные жесты между двумя окнами
в боковом и верхнем виде, линия приёма и Escape, отказ над страницей и при
открытом диалоге, сохранение CEF browser ID / DOM token / формы / cookies,
контейнера, закрепления и выключенного звука. Проверены переход в группу
