# M0 — foundation and compatibility probes

Обновление 18.10.2026: после сообщения о полном зависании ПК при восстановлении тестового окна
GPU-путь не считается стабильным. Linux M0 и обычный браузер теперь по умолчанию используют
Skia raster и CEF без аппаратного ускорения. Сведения о GPU ниже — исторические результаты,
которые не подтверждают стабильность minimize/restore. Повторного GPU-теста на рабочем столе не было.

## Цель и рабочая платформа

Собираемый C++20-проект, воспроизводимые зависимости и настоящее Linux-окно,
которое композиционирует кадры CEF OSR средствами Skia. По уточнению пользователя
**Linux — основная платформа разработки и проверки**. Windows-ветка остаётся дополнительной;
её проверка не является условием запуска и дальнейшей работы на Linux.

## Повторение проверок

```bash
ctest --preset linux-x64-release
python3 scripts/smoke_window.py
python3 scripts/smoke.py --software-rendering --extension-probe
./run.sh
```

GUI QA отправляет события только своему окну и использует локальный XIM (`XMODIFIERS=@im=none`)
для воспроизводимой синтетической раскладки. Настройки раскладки Wayland не меняются.
Эта проверка подтверждает передачу native events → CEF → DOM, но не весь системный IME.

## Устранённые интеграционные проблемы

1. Современный CEF на Windows использует sandbox bootstrap + client DLL вместо старой `cef_sandbox.lib`.
2. EGL/GLES DLL отсутствуют в выбранном CEF Windows runtime; ANGLE собирается отдельно.
3. Upstream zlib 1.3.2 использует явную GN-конфигурацию вместо несовместимых Chromium-private SIMD sources.
4. Патч генератора ANGLE обрабатывает non-ASCII bytes в GN response files до UTF-8 decoding:
   проект собирается в пути с кириллицей и пробелами.
5. Linux entry point имеет `NO_STACK_PROTECTOR`, как официальный cefsimple: zygote меняет
   stack guard при fork. `CefExecuteProcess` выполняется до создания объектов приложения.
6. Внешний CEF pump сочетает deadlines с резервным tick раз в 16 ms: без него наблюдалось зависание startup/MV3.
7. Для Linux desktop используется `ozone-platform=x11`, для capture — `headless`.
   Создаётся собственное X11-окно; CEF OSR получает его parent handle.
8. EGL context активируется перед каждой композицией; Skia Ganesh flush выполняется перед swap.
   Размер CEF view обновляется при ConfigureNotify с учётом заданного backing scale.

## Ограничения M0

- Linux host использует X11/XWayland; нативный Wayland ещё не реализован.
- GPU UI на Linux использует EGL/GLES3. Vulkan, выделенный render thread и production compositor — M2;
  60/120 fps этим этапом не подтверждаются.
- CEF web frames проходят через CPU OSR buffer и загружаются в Skia. Это ещё не GPU-only web bridge.
- Backing scale задаётся `--scale`; автоматическая смена масштаба между мониторами не реализована.
- XIM commit и caret path подключены. Полный цикл preedit/candidates CJK, dead keys и accessibility
  требуют отдельной ручной проверки. Windows IMM/TSF также не подтверждены.
- Frameless drag/edge resize/maximize/minimize подключены через EWMH; автоматический GUI smoke
  проверяет resize, caption close и темы. Остальные WM-жесты требуют ручной проверки.
- MV3 probe не подтверждает установку CRX, popup extensions и совместимость Chrome Web Store.
- Палитры переключаются live. System mode и анимации — M3.
- Полноценные вкладки, адресная строка, история, загрузки и настройки — следующие этапы.
