# M10 — частота монитора и синхронизированный CPU-вывод Linux

После оптимизации M9 пользователь всё ещё видел рывки колёсика на экране 120–165 Гц.
Уточнение выявило оставшийся жёсткий лимит CEF 60 FPS. Одних промежуточных scrollY/rAF
для проверки плавности недостаточно: они не подтверждают равномерный показ окна.

## Изменение

- CEF website/popup frame rate выбирается по частоте монитора, 30–360 Гц, вместо постоянных
  60 FPS для страниц и 30 FPS для расширений. Число доступно как tabs[].frame_rate.
- В Wayland-сессии отдельное read-only соединение читает wl_output (режим, частоту, координаты,
  transform и scale). Оно не создаёт surfaces или графических контекстов. Это важно, поскольку
  Xwayland может публиковать виртуальный RandR-режим 60 Гц при реальных 144 Гц Wayland output.
- В X11 используется текущий RandR mode монитора с наибольшей областью пересечения с окном.
  Проверка частоты раз в секунду обновляет уже открытые CEF-вкладки при изменении режима.
- SoftwarePresenter рисует Skia непосредственно в MIT-SHM backing store. Сегменты IPC_PRIVATE
  имеют права 0600; сервер подключается read-only. После attachment они помечены IPC_RMID.
  XSync после upload гарантирует, что сервер прочитал память до следующей записи CPU.
- Кадры загружаются в отдельные server-side pixmaps и передаются XPresent без Async/MayTear.
  Обновление окна больше не состоит из серии частей XPutImage.
- Два pixmap-буфера, максимум два запроса в полёте и последовательные target MSC ограничивают
  задержку. Пока буферы заняты, сохраняется актуальный CEF bitmap. После idle/presentation
  событий renderer продолжает работу; нет ожидания графических fence на UI thread.
- На resize старые pixmaps освобождаются, но их pending serial остаются до complete, поэтому
  частое изменение размеров тоже не создаёт неограниченную очередь.
- Если MIT-SHM недоступен, upload идёт через XPutImage в offscreen pixmap. Если Present отсутствует,
  готовый pixmap копируется в окно одним XCopyArea. XPresent и Xrandr загружаются опционально;
  Wayland client — обычная системная зависимость libwayland-client.so.0.

## Проверки

36 unit-тестов; GUI на закрытых Weston Pixman + Xwayland SHM с GLX disabled.
Новый параметр verify_browser.py --refresh=144 задаёт 144000 mHz для headless output.

Scrolling suite теперь сверяет реальный GetWindowlessFrameRate, частоту wl_output и отметки
завершения XPresent UST/MSC, проверяет очередь не более двух запросов и уникальные MSC
видимых samples. При копировании нескольких запросов в одном refresh sample содержит последний;
число superseded отдельно учитывается, не выдаётся за отдельные показанные кадры.

На 144 Гц проверены: оба направления колеса, вложенная/горизонтальная область, серия событий,
масштаб chrome 125%, окно 2200×1500 и корректное закрытие CEF. В обычном окне один шаг колеса
даёт 27–28 разных положений и 31 native submissions вместо прежних 12–13 и 14–15.
В финальном прогоне: median presentation interval 7.057 ms, p95 16.612 ms, skipped=0,
superseded=0, maximum_pending=2. Большое окно на CPU не гарантирует 144 показанных FPS:
частота производителя кадров и фактическая производительность различаются.

60 Гц также проходит проверку реальных интервалов (p95 <25 ms в длинной серии).
Резервный путь без обоих расширений отдельно проверен через AURA_X11_PRESENT=0 AURA_X11_SHM=0.
Interface/features suites проверяют resize/scale/restart, нативные диалоги, защиту, popup/pinning,
приватные вкладки и время жизни CEF при 144 Гц. Полное приложение на рабочем столе пользователя
не запускалось, GPU acceleration по умолчанию остаётся выключенным.

Build headers: X11/Xext, Xpresent, Xrandr, wayland-client. XPresent/RandR runtime libraries
опциональны благодаря dlopen; их Xlib close hooks сохраняются через RTLD_NODELETE.
